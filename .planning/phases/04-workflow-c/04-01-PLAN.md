```typescript
export const touchpoints = sqliteTable('touchpoints', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  clientId: integer('client_id').notNull().references(() => clients.id, { onDelete: 'cascade' }),
  type: text('type', { enum: ['email', 'call', 'stage_change'] }).notNull(),
  sourceId: text('source_id').notNull(),
  summary: text('summary').notNull(),
  metadata: text('metadata', { mode: 'json' }),
  occurredAt: text('occurred_at').notNull(),
  createdAt: text('created_at').default(sql`(datetime('now'))`),
}, (table) => ({
  clientIdx: index('touchpoints_client_idx').on(table.clientId, table.occurredAt),
  typeIdx: index('touchpoints_type_idx').on(table.clientId, table.type),
}));
```

## ThreadMessage shape (src/workflow/thread-loader.ts L28-44)
```typescript
export interface ThreadMessage {
  messageId: string;
  from: string;       // "Name <email@domain.com>" 또는 "email@domain.com"
  to: string;
  subject: string;
  body: string;       // plain text 또는 HTML
  internalDate: string;  // ms epoch 문자열
}
```

## Drizzle 마이그레이션 — SQLite text enum 특성
SQLite는 text 컬럼에 CHECK constraint를 걸지 않는 한 enum 제약을 DB 레벨에서 강제하지 않는다. Drizzle의 `text('type', { enum: [...] })`는 **TypeScript 타입 힌트용**. 따라서 touchpoints.type enum 확장은 DDL 없이 schema.ts의 enum 배열만 수정하면 된다. clients 컬럼 추가는 실제 ALTER TABLE 필요.

## 프로젝트 ESM 제약
프로젝트는 `"type": "module"` ESM 전용. import는 반드시 `.js` 확장자. CommonJS require 금지.

## Plan-specific Gotchas

1. **Legacy 'email' 레코드 카운트 기록 의무 (RESEARCH 오픈 질문 #2 응답):** Task 1에서 migration 직전에 `SELECT COUNT(*) FROM touchpoints WHERE type='email'` 값을 기록(커밋 메시지 또는 SUMMARY.md에). 이는 04-04 플랜이 workflow-a/b의 신규 레코드가 `'email_sent'`로 저장되기 시작한 뒤에도 기존 카운트가 **그대로 유지**되는지(손실 0) 검증하는 기준선이 된다.

2. **Drizzle SQLite enum은 DB 레벨 제약이 아님** — text 컬럼에 CHECK constraint 없이 enum을 추가/확장해도 DDL 변경 없음. 마이그레이션 파일에 touchpoints 테이블 DROP/CREATE가 뜨면 Drizzle이 다른 변경을 잘못 감지한 것 → 수동 삭제.

3. **getActiveFollowupClients 정렬 시 NULL 처리** — SQLite ORDER BY ASC는 NULL을 가장 앞에 둔다. lastContactDate가 NULL인 클라이언트는 "경과 일수 계산 불가"이므로 04-05 workflow-c가 skip 처리하지만, 정렬 자체는 null-first로 둔다. 테스트 케이스로 명시.

4. **followupPaused mode:'boolean'** — Drizzle이 SQLite integer 0/1 ↔ JS boolean을 자동 변환. `.where(eq(clients.followupPaused, false))` 는 내부적으로 `followup_paused = 0`으로 나감. 정상 동작 확인 필수.

5. **운영 DB 백업은 절대 생략 금지** — Phase 3 UAT에서 이미 실제 비즈니스 데이터가 쌓여있음. Task 1 첫 줄이 `cp` 백업 명령.
